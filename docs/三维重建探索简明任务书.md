# 三维重建探索：两周简明任务书

## 这两周要做成什么

我们不是写论文，也不追求“测出真实三维误差”。这两周只要回答一个实际问题：**哪种方法更适合放进我们的瓷器学习网站？**

两周后应拿到：

1. 4 种方法在同一批瓷器图片上的结果；
2. 一张简单对比表；
3. 每种方法 1 份 2～3 页小报告；
4. 一个结论：快速展示用什么、精细展示用什么、多张图时用什么；
5. 最好有 1 个能放进网页演示的模型。

## 不做什么

- 不做复杂的点云、Chamfer Distance、法线误差等论文指标；
- 不训练自己的三维大模型；
- 不要求所有方法都在自己的电脑本地跑通；
- 不为了跑通一个模型连续卡几天。一个方法安装/运行超过半天仍没有结果，就保留报错和原因，换备用方案。

## 我们自己的“小测试集”

不必先下载很大的专业数据集。先在项目已有的、来源许可明确的图片里挑 **6 张**，都裁成相近大小、正面居中。

| 图片类型 | 目的 |
|---|---|
| 简单圆瓶/罐 | 看基础器型是否稳定 |
| 长颈瓶 | 看口沿、颈部比例 |
| 碗或盘 | 看大开口能否生成 |
| 带耳/带把器物 | 看突出结构是否丢失 |
| 扁壶（可用 `images.jpg`） | 看厚度、双耳等难点 |
| 有青花或复杂纹饰的器物 | 看颜色和纹饰观感 |

把它叫作 `瓷器小样本测试集 v1` 就够了。每个人都必须使用这一模一样的 6 张图片；不要一人挑容易图片、一人挑难图片。

建议目录：

```text
benchmark/simple-v1/
  inputs/             # 6 张统一图片
  member-a/
  member-b/
  screenshots/        # 每个模型的正面、侧面、背面截图
  comparison.xlsx 或 comparison.md
```

## 只用这 5 个简单指标

每张图片、每种方法由大家一起看图打分，每项 1～5 分。

| 指标 | 怎么看 |
|---|---|
| 器型像不像 | 一眼能否看出原本是瓶、碗、扁壶等 |
| 细节有没有 | 口沿、器足、耳、把手是否存在且不离谱 |
| 颜色纹饰像不像 | 正面颜色、花纹是否接近原图 |
| 能不能用 | 能否转动、是否破面、是否能导入网页 |
| 速度是否能接受 | 首次运行多久、后续一次生成多久 |

不需要争论“4 分和 5 分的科学差异”。重点是保存相同角度的截图，让老师和组员都能看到区别。

每次运行另外记录：方法名、运行日期、电脑/显卡、耗时、成功或失败、输出文件格式、遇到的问题。

## 四种方法怎么分

4 种是**团队总共测试 4 种**，不是每个人硬装 4 种。对大三课设来说，一人负责 2 种更现实，也更容易讲清楚。

| 成员 | 负责方法 | 任务目的 |
|---|---|---|
| 队员 A | TripoSR、Stable Fast 3D（SF3D） | 都是单张图片生成，比较“现有方案”和“更适合纹理的升级方案” |
| 队员 B | Hunyuan3D、Meshroom | 比较高质量 AI 生成与多张图片摄影测量 |
| 队长 | 准备 6 张图片、统一记录表、帮助解决安装、汇总与演示 | 保证大家比较的是同一批图，最后把结论变成产品计划 |

### 备用规则

- Hunyuan3D 对显卡要求可能比较高；如果本机跑不动，先尝试其官方在线演示或改用 InstantMesh，并在报告中说明原因。
- Meshroom 不适合只用一张图。队员 B 需要对其中 **2 件器物补拍 12～20 张环绕照片**，再用 Meshroom 重建；其余单图方法仍用 6 张图片测试。
- SF3D 如果安装困难，可以先看官方示例结果、记录安装问题，再由队长决定是否改为 InstantMesh；不能因为一个环境问题拖慢整组。

## 每个人具体要做什么

### 队员 A：单图快速重建

1. 花半天看 TripoSR、SF3D 的论文摘要、项目 README 和演示图；
2. 在同一台电脑上跑 TripoSR 与 SF3D；
3. 每种方法跑 6 张测试图；
4. 每个结果保存 GLB/OBJ 和正、侧、背三张截图；
5. 填对比表，写出“它为什么快/慢、好/不好”；
6. 推荐其中一个是否适合替换现在项目里的 TripoSR。

### 队员 B：高质量和多图重建

1. 花半天了解 Hunyuan3D 和 Meshroom 分别解决什么问题；
2. 尝试 Hunyuan3D；如果跑不动，记录显卡、报错、需要的条件，不要死磕；
3. 对 2 件器物拍 12～20 张环绕照片：物体不动、光线尽量一致、相邻照片有重叠；
4. 用 Meshroom 生成一份多图模型；
5. 与单图 TripoSR 的同一器物结果并排截图；
6. 写出“多图有没有改善耳、厚度、背面、底部”。

### 队长：不要自己再多装四个模型

1. 第一天选好 6 张测试图，建好文件夹和统一表格；
2. 每两天开 15 分钟碰头会：每人展示 1 张成功图和 1 个问题；
3. 统一截图角度、统一评分方式，避免只挑最好看的图；
4. 帮大家处理项目接口、GLB 导入和网页展示；
5. 最后写团队总结：哪个适合“快速模式”、哪个适合“精细模式”。

## 两周时间表

| 时间 | 事情 | 完成标准 |
|---|---|---|
| 第 1～2 天 | 选 6 张图、看 README/摘要、确认显卡 | 每人知道自己要跑哪两种方法 |
| 第 3～5 天 | 跑第一个方法 | 至少产出 3 张图的模型和截图 |
| 第 6～7 天 | 跑第二个方法 | 6 张图基本跑完；跑不通要有原因记录 |
| 第 8 天 | 小组碰头 | 并排比较，不新增方法 |
| 第 9～10 天 | 补跑、挑最佳模型导入网页 | 至少 1 个模型在网页中能正常看 |
| 第 11～12 天 | 写个人小报告 | 每人 2～3 页即可 |
| 第 13～14 天 | 汇总、做 PPT | 有对比表、截图墙和明确结论 |

## 个人小报告模板（2～3 页就够）

```text
标题：XXX 方法在瓷器图片三维重建中的测试

1. 这个方法是什么（半页）
   - 它输入什么、输出什么、适合什么场景

2. 我怎么测试的（半页）
   - 使用哪 6 张图、电脑配置、是否成功跑通

3. 结果展示（1 页）
   - 放 2～3 组输入图 + 三维模型截图
   - 简单表格：耗时、能否导出、五项打分

4. 我发现的问题和结论（半页）
   - 最好的一点、最差的一点
   - 是否建议放入“器见千年”，为什么
```

## 多模态先做成“小彩蛋”，不要抢主线

本轮主线仍然是把四种重建方式比较清楚。图文多模态只在最后选 **2 张图片** 做一个小实验：

1. 让视觉大模型给图片写一段简短描述，例如“青花、扁圆器身、两侧有耳、正面可见花纹”；
2. 把这段描述展示在重建结果旁边，或用于搜索文物库中的相似器物；
3. 如果某个模型本身支持文字条件，再试一次“有描述/无描述”的效果；
4. 截图比较，诚实写出有没有帮助。

这里最重要的原则是：**大模型写出的文字是辅助描述，不是文物鉴定结论。** 没有来源就不要写具体朝代、窑口或背面纹饰。

## 最后要对老师说的结论

> 我们没有把单图三维重建当成真实扫描，而是用小样本测试集比较了不同方法在瓷器上的实际表现。结果会把“快速生成”“高质量展示”和“多视角精细重建”分开使用：单图适合学习展示，多图更适合复杂器物的结构还原。
