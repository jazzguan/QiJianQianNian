# 《器见千年》未来项目规划报告

> 规划周期：2026-11 至 2027-05  
> 建议参赛名称：器见千年——面向移动端的 AI 文物三维互动学习智能体

## 一、未来目标

将现有 Web 原型升级为可在 Android 移动终端稳定运行的文物学习智能体。用户拍摄一件陶瓷器物后，系统能够生成三维学习对象，提示可见与不可见区域，自动提取形态参数，并连接可信馆藏资料，引导用户完成观察、比较、提问和测评。

## 二、拟形成的核心创新

### 1. 不确定性感知的单图三维学习

不把单图重建包装成高精度扫描，而是明确展示正面可信区域、遮挡推断区域和模型置信度。结合多视角补拍引导，让用户主动改善重建质量。这既提升科学性，也能形成区别于普通“图片转 3D”应用的创新点。

### 2. 可计算的文物形态演化

对器口、器颈、器腹和器足进行语义分段，建立轮廓、比例和关键参数的统一表示；用户可比较不同时期器物，并看到差异来自哪些几何部位，而不只观看静态时间轴。

### 3. 有证据的多模态学习智能体

AI 回答必须绑定馆藏条目、文献片段和模型测量结果；系统区分“资料事实、视觉观察、模型推断”，避免把猜测写成文物鉴定结论。语音、图片、三维选区和学习记录共同构成上下文。

### 4. 个性化学习闭环

依据用户观察行为、错误类型和已掌握知识点生成下一步任务，让“看文物”转化为可衡量的学习过程。教师端可创建专题任务并查看班级掌握情况。

## 三、重点建设内容

| 优先级 | 建设项 | 验收结果 |
| --- | --- | --- |
| P0 | 解耦 Gemini 与 TripoSR，加入离线降级 | 无密钥、断网时仍可完成本地重建 |
| P0 | Android 端交付 | 可安装 APK，支持拍照、上传、触控查看和语音提问 |
| P0 | 现场稳定性 | 预置演示数据，一键启动，失败可恢复，无敏感密钥进入客户端 |
| P1 | 多视角补拍与不确定性提示 | 系统提示缺失视角，并展示重建可信区域 |
| P1 | 形态语义分割与参数对齐 | 自动识别器口、颈、腹、足并输出可解释差异 |
| P1 | 可信知识库扩充 | 馆藏扩展至至少 100 件，每条事实保留来源与许可 |
| P1 | 量化评测 | 形成重建、问答、性能和学习效果四类实验结果 |
| P2 | 教师端与课程任务 | 支持布置任务、查看学习进度和导出报告 |

## 四、评测设计

- **三维质量**：轮廓 IoU、关键尺寸相对误差、Chamfer Distance，以及补拍前后的质量变化。
- **AI 可信度**：引用正确率、问题可回答率、无依据陈述率和人工专家评分。
- **移动性能**：首屏时间、三维加载时间、平均帧率、重建耗时、峰值显存和失败恢复率。
- **学习效果**：邀请目标用户完成前测、使用和后测，对比知识正确率、任务完成时间与使用满意度。

## 五、实施节奏

### 第一阶段：稳定主链路（2026-11）

完成离线重建、子模块修复、模型预下载、异常恢复、Android 壳与一键部署；确定三分钟答辩演示脚本。

### 第二阶段：形成创新证据（2026-12 至 2027-01）

完成多视角补拍、不确定性表达、形态语义分析和可信 RAG；建立标杆数据集并产出第一版实验结果、Beta 安装包和演示视频。

### 第三阶段：区域赛打磨（2027-02 至 2027-04）

扩充馆藏与课程内容，完成用户研究、性能优化、测试文档、高层设计、开源说明和创新性分析。

### 第四阶段：决赛准备（2027-05）

冻结功能，集中进行真机兼容、压力测试、现场断网演练、答辩材料和演示节奏训练。

## 六、预期成果

- Android Beta/APK、Web 管理端和可复现后端部署包。
- 不少于 100 件来源清晰的馆藏知识库及一组高质量三维标杆数据。
- 一套不确定性感知重建、形态演化分析和证据约束问答方法。
- 软件著作权/专利材料、测试报告、用户研究报告、演示视频和完整竞赛文档。

## 七、取舍原则

未来版本应优先证明“真实用户为什么需要、核心技术为什么不同、效果如何被验证”。不建议同时扩展大量文物品类、社交、电商或虚拟展厅；先把瓷器学习场景做到稳定、可信、可量化，再考虑平台化复制。
