# 两周三维重建探索与基准评测计划（v0.1）

## 1. 目标与边界

目标不是在两周内“找一个看起来最炫的模型”，而是为“器见千年”确定可落地的三维重建路线：

1. 单图输入时，比较几何、纹饰外观、耗时、显存与 Web 可用性；
2. 多图输入时，验证是否能显著改善器耳、扁壶厚度、背面与底部；
3. 做一个小规模的“图像 + 检索得到的文本”探索，验证文本信息是否能提升结果或候选选择；
4. 产出可复现的证据，而不是只保留若干效果图。

**不在本轮目标中：** 文物级测绘精度、模型微调、完整训练新模型、把所有候选模型都接入产品。单张图片不可见区域仍属于模型推断，报告和产品中必须明确说明。

## 2. 基准设计：公开真值集 + 项目瓷器集

没有一个现成基准同时覆盖“中国瓷器、单图生成、真实网页部署、图文条件”四个问题。因此建立一个**小型、可复现的项目基准**，同时使用公开数据避免只凭主观印象。

### 2.1 第一层：公开真值集（`ceramic-gt-8`）

首选 [LR3D-CULT](https://data.mendeley.com/datasets/j5wd88d559/1)：它提供越南陶瓷文物的网格和多视角图像，可用于少视图/多视图重建。每个样本只取一张正视输入，保留其余视图与网格作为真值评测依据。下载前由队长核对许可证、数据版本与引用要求。

从可用对象中按下列标签各选 1 件，共 8 件：

| 标签 | 应覆盖的难点 |
|---|---|
| `simple-round` | 简单、近似轴对称的瓶或罐 |
| `tall-neck` | 长颈、口沿细节 |
| `wide-mouth` | 碗/盘类的大开口 |
| `flat-body` | 扁壶或近似扁平器 |
| `handle` | 单耳/双耳等突出结构 |
| `lid-or-foot` | 盖、圈足或底部结构 |
| `blue-white-pattern` | 高对比度青花/复杂纹饰 |
| `dark-or-glossy` | 深色、高光或低纹理表面 |

如果 LR3D-CULT 下载、许可证或格式不适配，则用 [OmniObject3D 的生成评测数据](https://github.com/omniobject3d/omniobject3d/tree/main/benchmarks/3d_generation)中“tableware / vase / bowl”类别替代；它提供扫描网格和多视图渲染。不要用没有真值网格的网络图片替代这一层。

### 2.2 第二层：项目相关集（`qjqn-ceramic-8`）

从项目已收录且来源、许可清楚的馆藏照片中选 8 张；若补拍实物，必须记录拍摄者与授权。该集合用于评估产品观感与文物特征，而不是计算真实几何误差。

仍按上表 8 个难点选样，并为每件建立 `metadata.json`：

```json
{
  "id": "qjqn-01",
  "source_url": "...",
  "license": "...",
  "type": "月牙/扁壶/梅瓶等（有来源才填写）",
  "visible_features": ["双耳", "蓝白纹饰"],
  "input_view": "front",
  "notes": "高光、背景复杂、局部遮挡等"
}
```

### 2.3 固化输入与目录

队长在第 2 天冻结 `benchmark/v0.1/manifest.csv`。所有方法使用同一份原图与同一裁剪框；统一输出最长边 512px（另保留原始文件）。若某官方方法要求透明背景或特定尺寸，允许按其官方预处理执行，但必须在 `run.json` 记录。

```
benchmark/v0.1/
  manifest.csv
  inputs/{sample_id}.png
  ground_truth/                 # 仅公开真值集
  references/{sample_id}/       # 留出的多视角参考图
  runs/{method}/{sample_id}/
    output.glb | output.obj
    preview-front.png
    preview-back.png
    run.json
  scores.csv
```

## 3. 统一实验协议与指标

### 3.1 必须记录的工程信息

每次运行记录：方法和版本/commit、权重版本与许可证、设备/显卡/显存、CUDA/PyTorch、输入预处理、随机种子、开始结束时间、峰值显存、是否成功导出 Web 可读取 GLB、文件大小、面数、顶点数与报错日志。

每个方法每张图最多重试 **2 次**；第 3 次仍失败即计为失败，不无限调参。新增环境或模型安装最多花 **2 小时**；超时后保留日志、标为“本机未复现”，改测备用方法。

### 3.2 自动指标（只在 `ceramic-gt-8` 使用）

输出网格先统一缩放到单位包围盒，使用 ICP 做刚体对齐；从预测与真值表面各均匀采样 100,000 点。

| 维度 | 指标 | 趋势 |
|---|---|---|
| 几何 | 对称 Chamfer Distance（CD） | 越低越好 |
| 几何 | F-score@1% / 2% 物体尺度 | 越高越好 |
| 表面 | 法线一致性 | 越高越好 |
| 多视角外观 | 留出视角的掩码 IoU、LPIPS（可实现时） | IoU 高、LPIPS 低更好 |
| 拓扑 | 是否水密、连通分量数、非流形/破洞提示 | 水密、少异常更好 |
| 工程 | 成功率、推理时间、峰值显存、GLB 大小 | 更稳定、快、轻更好 |

任何缺失指标都填 `NA` 并说明原因，不能用 0 代替。

### 3.3 瓷器特征人工盲评（两个集合都做）

队长将渲染图匿名为 `M01/M02/...`，不显示方法名称。两名非产出该结果的成员独立打分，取平均值；差异超过 2 分时复核。

每项 0–5 分：

1. 外轮廓与器型比例；
2. 口沿、圈足、盖等结构；
3. 耳、把、镂空和扁平厚度等突出结构；
4. 正面纹饰/色彩与输入一致性；
5. 背面与遮挡区是否自然，并明确标识其为推断；
6. 网格与材质是否可直接放入 Three.js 网页查看。

**说明：** 纹饰观感好不等于真实复原；单图看不到的背面不能因为“想象得漂亮”而给高真实性分。

### 3.4 决策方式

不做掩盖短板的单一“总分”。先列各项原始排名，再按产品场景做三条结论：

- 快速单图默认引擎：优先成功率、时间、Web 可用性、前视外观；
- 精品离线生成引擎：优先 GT 几何、纹理、复杂器型分数；
- 多视角精确模式：优先几何误差与可观测区域覆盖。

## 4. 方法分工

所有人先阅读论文/README，形成一页“方法卡”，再安装和复现。每人测 4 个方法；同一种方法只有一个负责人，避免重复劳动。

| 角色 | 负责方法（4 个） | 重点问题 | 最低交付 |
|---|---|---|---|
| 队员 A：快速单图 | TripoSR（现有基线）、Stable Fast 3D、InstantMesh、Wonder3D | 能否快速、稳健地生成可用于网页的带纹理网格 | 32 个核心输出、方法卡、指标表、故障清单 |
| 队员 B：高质量与多视角 | Hunyuan3D 2.1、TRELLIS、TRELLIS.2、COLMAP 或 Meshroom | 复杂结构、PBR/纹理与多视角真实几何的上限 | 32 个核心输出或完整不可复现证据、方法卡、指标表、故障清单 |
| 队长：基准、评测与图文探索 | 不重复跑 8 个主方法；必要时协助最有希望的 2 个 | 固化数据/脚本、匿名盲评、结果汇总、图文 A/B 原型、最终选型 | 基准包、汇总报告、推荐接入方案、答辩图表 |

### 显存与平台门槛

先执行 `nvidia-smi` 并在 `manifest` 中登记。Hunyuan3D 2.1 官方说明中，形状生成约需 10GB 显存、纹理约需 21GB；TRELLIS 官方要求至少 16GB NVIDIA 显存且主要在 Linux 测试。若硬件不满足，负责人不能“硬拖两周”，应在第 2 天说明，保留安装日志并与队长换成可运行的候选方法或云端一次性验证。

SF3D 是 TripoSR 的直接升级候选：官方称它增加 UV 展开、去光照和材质参数预测，适合优先接入现有 FastAPI + Three.js 链路。Hunyuan/TRELLIS 的定位是高质量离线输出；COLMAP/Meshroom 是多视角真实几何对照，不应与单图方法混成同一排名。

## 5. 图文多模态探索：做“证据增强”，不让模型编造文物知识

本轮不承诺“文本一定让单图几何变准”。先做一个可解释的 A/B 小实验，选择 4 张难样本，比较：

- **A：Image-only**：只给重建模型图片；
- **B：Image + 结构化描述**：视觉模型先输出 `器型、轮廓、口沿、耳/把、盖、主色、纹饰、可见/不可见部位`，再检索项目文物库或有许可的馆藏资料，生成带来源的短描述；
- **C：Image + 结构化描述 + 候选重排**：同一图像生成 2–4 个候选模型，用图文一致性和人工盲评选择候选。

流程如下：

```
单张图片
  -> 视觉模型提取“可见事实”（JSON，含置信/不确定项）
  -> 只在可信馆藏资料中检索相似器物
  -> 生成带 source_url 的短文本条件
  -> 支持图文条件的方法直接使用；不支持的模型用于候选重排
  -> 与 Image-only 对照
```

禁止把大模型猜出的朝代、窑口、背面纹饰当作事实喂回系统；检索没有证据时应写“未知”。文本的主要价值是器型先验、方法选择和候选重排，而不是伪造不可见几何。

评价新增三项：可见特征覆盖率、文本/模型一致性、错误知识注入次数。只有在 B/C 明显优于 A 且不增加错误知识时，才考虑接入产品。

## 7. 每位队员的报告模板（建议 4–6 页）

1. **方法卡**：论文/官方仓库、核心思路、输入输出、许可证、硬件要求；
2. **复现环境**：命令、版本、设备、问题和解决方式；
3. **定量结果**：`ceramic-gt-8` 的原始指标表，不只放平均值；
4. **定性结果**：每个难点至少一组“输入—正面—侧面—背面—网格”对比；
5. **失败案例**：至少 2 个，并分析是遮挡、反光、分割、纹理还是模型先验问题；
6. **工程判断**：能否进入本项目、接入成本、预估显存/时延、许可证风险；
7. **结论**：推荐它作为快速、精品还是不推荐，以及证据。

## 8. 最终团队交付与选型门槛

最终交付物：`benchmark/v0.1`、两份个人报告、一份总报告、原始 GLB/渲染图/日志、可复现命令、以及 5 页以内答辩附录。

只有同时满足以下条件的模型，才进入产品接入候选：

- 至少完成 8 张核心图中的 7 张；
- 能导出 Three.js 可加载的 GLB，或有明确稳定的转换链路；
- 输出许可证与权重许可可用于本项目场景；
- 在复杂样本（扁壶/双耳/复杂纹饰）中不比当前 TripoSR 更差；
- 有明确的失败提示与降级路径。

建议最终产品架构为：**SF3D/TripoSR 快速单图模式 + COLMAP/Meshroom 多视角精确模式 + Hunyuan3D/TRELLIS 精品离线模式**。先用评测结果决定真正接入哪一个，不提前宣布“某模型最好”。
